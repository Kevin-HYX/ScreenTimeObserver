# 屏幕时间观测器 · 部署说明

M1 阶段产物：一个开机自动运行、不需要人工干预的屏幕时间采集器。数据只落本地。

## 一、目录结构

```
D:\ScreenTimeObserver\
  collector.exe            常驻进程（GUI 子系统，无控制台窗口，带托盘图标）
  collector-cli.exe        同一份源码编译的控制台版，用于命令行操作
  config.json              运行时配置
  data\YYYY-MM-DD.jsonl     每日数据，一行一条记录
  data\screenshots\         虚拟桌面原尺寸 PNG，滚动保留约 24 小时
  data\wifi\YYYY-MM-DD.jsonl 附近 Wi-Fi 指纹，滚动保留 15 天
  logs\collector.log       运行日志（超过 2MB 自动轮转）
  logs\status.json         实时状态，每 10 秒刷新
  paused.flag              存在即表示"人工暂停中"，托盘或命令行控制
  assets\logo.svg          标识定稿源（矢量）
  assets\logo.ico          多尺寸图标（16/20/24/32/40/48/64/128/256）
  assets\logo-mono.ico     深色任务栏用的纯白版
  assets\preview-sizes.png 标识在 6 种尺寸、明暗两种底色下的质检图
  src\                     Go 源码、build.cmd（编译）、build-icons.py（出图标）
  docs\                    文档
```

## 二、日常操作

托盘图标（右键菜单）：

- **暂停采集 / 继续采集**：暂停期间不记录任何窗口细节，只写暂停标志，AI 事后能明确看出"这段时间是人工暂停"
- 暂停期间也不会产生桌面截图；过期截图清理仍继续执行
- **打开数据目录**
- **复制数据目录**：把数据目录路径放进剪贴板，方便直接粘给别的程序或 AI；成功后会弹一次托盘气泡提示
- **启用 / 停用 Wi-Fi 位置指纹**：首次启用由用户在托盘点击，Windows 如弹出精确位置授权请选择允许
- **打开 Windows 位置权限设置**：权限被拒绝时直接跳转到系统设置

### 托盘图标的状态

图标本身随状态变化，不用悬停就能看出系统现在怎么样：

| 图标 | 状态 | 含义 |
|------|------|------|
| 蓝色时钟 | 记录中 | 正常采集，人也在用 |
| 灰色时钟 | 空闲中 | 已锁屏、系统休眠，或超过 180 秒没有键鼠输入 |
| 琥珀色暂停条 | 已暂停 | 你手动暂停，不记录任何窗口细节 |
| 红色感叹号 | 采集异常 | 前台事件钩子失效，或最近 10 分钟有数据/截图写盘失败 |

### 空闲与观看的区别

系统键鼠空闲超过 idle_threshold_sec（默认 180 秒）时，采集器会再问一次系统：默认播放设备上有没有声音在放。

- 有声音：说明人在看视频或在听东西，屏幕上有内容。状态记为 media，不算空闲，时长计入该应用。
- 没声音：记为 idle，只表示人离开了电脑，这部分不计入任何应用的占用。

这样「看 20 分钟视频没动鼠标」会算成观看而不是离开，而「出门两小时」仍然是空闲。
查询只发生在疑似空闲时，正常操作电脑的过程中完全不碰音频接口。
判定依据是设备峰值音量，所以静音看视频仍然会被算成空闲。
每条记录都保留原始 idle_sec，规则以后再调整，历史数据可以重新判定。

除了颜色，内部图形也会变（时钟指针 / 暂停条 / 感叹号），所以不依赖辨色能力。
从异常恢复正常时会弹一次气泡，进入异常时也会弹一次并说明卡在哪一环。
浅色任务栏用深色显示器轮廓，深色任务栏用白色轮廓，两种主题的环形颜色一致。
状态图标放在 assets/states/，命名是 <主题>-<状态>.ico；文件缺失时会回退到 logo.ico 并写日志。
- **退出采集器**

命令行（`collector-cli.exe`）：

```
collector-cli.exe status                      # 看实时状态
collector-cli.exe status --json               # 同上，机器可读
collector-cli.exe pause                       # 暂停（等价于点托盘）
collector-cli.exe resume                      # 恢复
collector-cli.exe review                      # 复看今天：连续性、空洞、重复、时间去向
collector-cli.exe review --date 2026-09-16 --json
collector-cli.exe once                        # 采一次样打印，用于排查
```

## 三、开机自启与守护

计划任务 `ScreenTimeObserver-M1`：

- 触发：当前用户登录时
- 设置：失败后每 1 分钟重启，最多 3 次；无执行时限；单实例策略=忽略新实例
- 进程本身还有命名互斥体做单实例保护，重复启动会直接退出（退出码 3）

手动停/起（改完配置后用）：

```
Stop-Process -Name collector -Force
Start-ScheduledTask -TaskName ScreenTimeObserver-M1
```

## 四、数据格式

每行一个 JSON 对象，字段固定（不做省略），方便直接读或交给 AI 分析：

| 字段 | 含义 |
| --- | --- |
| ts | 本地时间，毫秒精度，带时区偏移 |
| epoch | Unix 时间戳（秒，毫秒精度），便于计算 |
| event | start / change / heartbeat / paused / resumed / carry_over / offline / online / stop |
| reason | 触发原因：process_start / foreground / idle_threshold / reconcile / heartbeat / paused / resumed / new_day / system_suspend / system_resume / session_end / tray_exit |
| session | active / locked（锁屏）/ suspended（系统休眠）/ paused（人工暂停） |
| process | 前台进程名，如 chrome.exe |
| pid | 前台进程 PID |
| title | 窗口标题（最长 300 字） |
| window_class | 窗口类名，供后续清洗用 |
| idle_sec | 距上次键鼠输入的秒数（系统级输入时间戳） |
| idle | 是否已达到空闲阈值（默认 180 秒） |
| locked | 是否锁屏 |
| paused | 是否处于人工暂停记录 |
| since_prev_sec | 距上一条记录的秒数（跨进程重启也能算，启动时从文件尾部取回） |
| gap | since_prev_sec 是否超过 90 秒，即"这一段没有记录" |
| uptime_sec | 仅 stop 记录：本次运行了多久 |

写入策略：**状态变化才写**（前台窗口变、空闲翻转、锁屏、休眠），另外每 60 秒写一条心跳用于证明"我在跑且连续"。所以文件大小由状态变化数量决定，而不是轮询次数。

## 五、怎么判断"没有空洞"

1. `review` 会直接给出空洞清单与真空洞合计时长
2. 每条记录自带 `since_prev_sec` 和 `gap`，直接翻文件也能看出来
3. 两类空洞要区分：
   - `offline → online` 之间：机器睡眠/关机，属正常
   - 其他：进程没在跑（崩溃、被结束任务），属异常，需要查 `logs\collector.log`
4. `review` 还会报"疑似重复记录"：状态完全相同却不是心跳的连续记录

## 六、采集机制（为什么这么设计）

- **前台窗口**：`SetWinEventHook(EVENT_SYSTEM_FOREGROUND + EVENT_SYSTEM_MINIMIZEEND)` 事件驱动，每次切换都触发，不做窗口轮询；每 30 秒一次对账兜住漏掉的事件（对账发现状态不一致会记一条 `reason=reconcile`）
- **空闲判定**：`GetLastInputInfo`，它就是系统维护的键鼠输入时间戳，本身已是事件级；每秒采一次拿秒数，阈值 180 秒（与 ActivityWatch 默认值一致）
- **没挂键鼠低级钩子**：那会让每一次全系统键鼠输入都先过本进程，高回报率鼠标下会真实增加输入延迟，而拿到的额外信息对本用途没有帮助
- **写盘独立线程**：磁盘 IO 不阻塞消息循环，钩子回调永远秒回
- **原始数据不脱敏**（数据只在本机）但保留了 `window_class` 与进程名，后续要做脱敏/清洗时无需重新采

## 八、截图采集与隐私边界

- 每 60 秒抓取一次 Windows 虚拟屏幕，多个显示器按其系统布局合成一张原尺寸 PNG；鼠标指针一并记录
- 截图写入 `data\screenshots\`，文件名如 `20260915_214500.123_+0800.png`，包含本地时间与时区
- 约每 10 分钟清理一次修改时间早于 24 小时的文件，因此实际保留上限约为 24 小时 10 分钟
- 不记录输入内容、不联网；数据与截图均不上传
- 人工暂停期间不记录任何窗口细节，只留"这里是暂停"的标志
- 人工暂停期间不截图，恢复后立即继续
- 数据全部在 `D:\ScreenTimeObserver\data`，随时可删

## 九、Wi-Fi 位置指纹

- 每 5 分钟把附近网络的 SSID、SSID 原始字节十六进制、BSSID、信号强度、质量、频率与信道写入 `data\wifi\YYYY-MM-DD.jsonl`
- 为降低无线电与系统开销，缓存快照每 5 分钟读取一次，主动扫描最多每 30 分钟一次；连接变化、系统唤醒、人工恢复时会立即主动扫描
- 每约 10 分钟清理一次，按日期文件滚动保留 15 天；`enabled.flag` 与非本模块文件不会被误删
- 人工暂停时不采集 Wi-Fi 细节，但保留期清理继续；停用后同样不再采集
- 权限拒绝、无线电关闭、无适配器、WLAN 服务停止、扫描失败与扫描超时都会写成明确状态，不会伪装成“附近没有网络”
- Windows 新版本把 BSSID 与扫描结果视为精确位置。首次启用必须由用户在托盘发起授权，之后随采集器自启，无需重复操作

Wi-Fi 文件完全留在本机，不含网络密码、IP 地址、本机 MAC、已保存网络配置文件，也不上传。

## 十、重新编译与改标识

```
cd /d D:\ScreenTimeObserver\src
build.cmd                     # 产出 ..\collector.exe 与 ..\collector-cli.exe
python build-icons.py         # 由 assets\logo.svg 重新生成 ico 与质检图
```

标识定稿源是 `assets\logo.svg`（彩色）与 `assets\logo-mono.svg`（深色任务栏单色版），两者几何完全一致。改完跑 `build-icons.py`，看 `assets\preview-sizes.png` 确认 16px 是否还立得住。

## 十一、已知限制

- 部分应用（飞书、腾讯视频、Electron 类应用）窗口标题不够细，看不到"具体在看什么"；M1 不要求解决，后续可用浏览器扩展 / 媒体会话补
- 浏览器标签内部正在看什么，本采集器拿不到（标题通常只到页面标题）
- Windows 可能把新出现的托盘图标收进溢出区，第一次需要在任务栏设置里把它拖出来固定
- 单次采样之间的瞬时切换不再丢失（事件驱动），但**同一窗口内的标签切换**不产生前台窗口事件，采不到
## 十二、开机自启与验证

自启有**两条互相独立的链路**，任一条生效即可（进程内有单实例保护，重复启动会自动退出，不会出现两个进程）：

1. **计划任务** `ScreenTimeObserver-M1`
   - 触发：当前用户登录时；交互式令牌；普通权限（不需要管理员）
   - 失败处理：每 1 分钟重试，最多 3 次；无执行时限；空闲不停止；电池供电不阻止启动；单实例策略=忽略新实例
2. **注册表自启项** `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
   - 名称 `ScreenTimeObserver`，值 `"D:\ScreenTimeObserver\collector.exe"`

查看或修改（不需要管理员）：

```
schtasks /Query /TN ScreenTimeObserver-M1 /V /FO LIST
schtasks /Change /TN ScreenTimeObserver-M1 /DISABLE
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run'
Remove-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' -Name ScreenTimeObserver
```

**重启后怎么确认它自己起来了**：双击 `查看状态.cmd`，或跑 `collector-cli.exe status`，最后一段直接给结论：

```
—— 开机自启检查 ——
系统本次开机       2026-09-15 21:03:11（已开机 00h04m12s）
采集器本次启动     2026-09-15 21:03:38  → ✓ 是本次开机之后起来的，自启生效
```

注意两点：

- 采集器需要**登录后的桌面会话**（要读前台窗口），所以是"登录时自启"而不是"开机即启"。停在登录界面不登录时它不会启动，那段时间也不会被记录，属预期。
- 它的托盘图标在系统托盘里；Windows 可能把新图标先收进溢出区，第一次需要拖出来固定。
